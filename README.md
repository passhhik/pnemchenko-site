# Портфолио с интерактивной головой

Белый лист, логотип-подпись, 3D-голова по центру и три папки разделов из матового стекла. При загрузке голова собирается по частям: глаза, рот, очки, пирсинг, мозг в стикерах — и кожа. Она следит за курсором, говорит субтитрами, тянется как резиновая; очки снимаются. Каталог — папки проектов на дуге, фон при наведении окрашивается в стиль проекта. Кейсы собираются из блоков в админке и публикуются на сайт одной кнопкой. Если посетитель затих, голова его окликает, а если «залип» надолго — заплёвывает экран.

## Запуск на своём компьютере
Сайту нужен локальный сервер: двойной клик по `index.html` не сработает.

- **Проще всего:** двойной клик по `start.command` в папке сайта. Откроется окно Терминала и браузер с админкой. Если macOS не даёт запустить файл — правый клик → «Открыть». Если пишет «нет прав», один раз выполните в Терминале `chmod +x ~/Desktop/portfolio-head/start.command`.
- **Вручную:**
  ```bash
  cd ~/Desktop/portfolio-head
  python3 -m http.server 8765
  ```
  Сайт — http://localhost:8765, админка — http://localhost:8765/admin/

## Админка
Адрес: `…/admin/` — и на компьютере, и на опубликованном сайте. Слева — проекты (порядок в списке = порядок в каталоге; перетаскивайте или двигайте стрелками). В середине — форма. Справа — живой предпросмотр: кейс, папка в каталоге, вид с телефона.

Работать можно тремя способами, их можно сочетать.

**1. С сайтом — правки публикуются прямо из админки.** Нажмите «Подключить сайт» и один раз вставьте токен доступа к репозиторию на GitHub (как его получить — ниже). Дальше:
- содержимое открывается прямо с сайта, самое свежее;
- кнопка «Опубликовать» (или ⌘S) отправляет тексты и новые картинки на сайт. Через минуту-две админка напишет «Опубликовано» — правки уже видны посетителям;
- работает в любом браузере и с любого компьютера.

**2. С папкой сайта на компьютере** (Chrome или Edge). «Выбрать папку сайта» → укажите `portfolio-head` и разрешите изменение файлов. «Сохранить» (⌘S) записывает `content/site.json`, `content/projects.json` и новые картинки прямо в папку; прежняя версия содержимого уходит в `content/backup/` (хранятся последние 12 сохранений). Если к папке подключить ещё и сайт, рядом появится «Опубликовать»: она сохраняет в папку и отправляет на сайт содержимое со всеми картинками, которых там ещё нет. Так удобно готовить кейс черновиком и выкладывать, когда готов.

**3. Без сайта и без папки** — изменения скачиваются архивом, который нужно распаковать в папку сайта.

### Как получить токен для «Подключить сайт»
Токен — это ключ, по которому админка имеет право менять файлы в репозитории сайта. Создаётся один раз, занимает две минуты:
1. На GitHub: фото профиля → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Прямая ссылка есть в окне «Подключить сайт».
2. Token name — любое, например «Админка портфолио». Expiration — срок действия; когда он выйдет, админка попросит новый токен.
3. Repository access → Only select repositories → `pnemchenko-site`.
4. Permissions → Repository permissions → Contents → Read and write. Остальное не трогайте.
5. Generate token → скопируйте строку `github_pat_…` и вставьте в админку.

Что важно знать:
- Токен хранится только в вашем браузере и уходит только на `api.github.com`. Он даёт доступ к одному репозиторию. Кнопка «отключить» в шапке админки стирает его из браузера; отозвать совсем — на той же странице GitHub.
- Подключить сайт можно только по защищённому адресу: `https://…/admin/` или с этого компьютера (`start.command` → `localhost`). По `http://` админка токен не примет.
- Если на сайте за это время появилась другая версия содержимого (правили с другого компьютера), админка спросит, прежде чем заменить её вашей.
- GitHub пересобирает сайт после каждой публикации — не чаще десяти раз в час. Пишете большой кейс — публикуйте, когда готов кусок, а не каждую запятую.
- После «Опубликовано» на сайте всё ещё старое? Обновите страницу (⌘⇧R): браузер мог держать прежние файлы, а GitHub изредка раздаёт старую версию ещё несколько минут.
- Если админка пишет «GitHub не собрал сайт» или правки не появляются дольше десяти минут — откройте в репозитории вкладку Actions: там видно, что случилось со сборкой, и её можно перезапустить (Re-run jobs).

Что умеет:
- **Основное:** название, раздел, год, короткое описание, роль, клиент, команда, срок, теги, адрес страницы, переключатель «На сайте» (черновики видны только в админке).
- **Папка и фон:** обложка, наклейка на папке, цвет фона проекта (сразу показывает, читается ли на нём текст), цвет самой папки, работы проекта.
- **Результаты:** цифры и «суть в трёх абзацах» — задача, что сделал, результат.
- **Блоки:** текст, картинка, галерея, цифры, цитата, шаги, «до / после», видео, палитра. Порядок меняется перетаскиванием. У картинки есть ширина (в колонку текста, широкая, во весь экран) и подложка; у блока — реплика головы, которую она скажет, когда блок доедет до середины экрана.
- **Настройки сайта:** имя, роль, почта и Telegram, резюме, логотип, разделы, английская версия. Папки на главной расставляются мышью прямо в предпросмотре.
- **Картинки** при загрузке уменьшаются до разумного размера и сохраняются в WebP в `assets/cases/<адрес-проекта>/`. Прозрачность определяется сама («без фона»).
- Внизу формы — **проверка перед публикацией**: чего не хватает кейсу.

В Safari и Firefox нет доступа к папкам на компьютере: там подключайте сайт (способ 1) или скачивайте изменения архивом.

Удалённые в админке картинки и проекты из папки и из репозитория не стираются — лишние файлы в `assets/cases/` можно убрать вручную.

## Скелет кейса
Нанимающий читает по диагонали, поэтому кейс устроен «от итога к деталям»:

1. **Шапка на цвете проекта:** название, одна фраза о сути, факты (год, роль, клиент, команда, срок), обложка.
2. **Результаты в цифрах** — крупно, первым экраном белого листа.
3. **Суть в трёх абзацах:** задача → что сделал → результат.
4. **Блоки** — подробности для тех, кто дочитал: контекст и проблема → решение крупно → процесс по шагам → детали галереей → отзыв.
5. **Теги, контакт, следующий проект.**

Новый проект в админке создаётся с этим скелетом; пустые блоки на сайте не показываются.

## Перед публикацией
- Впишите в «Настройках сайта» почту и Telegram: без них в конце кейса нет кнопки «Написать».
- Загрузите резюме: пока файла нет, кнопка CV скрыта.
- В `index.html` в строке `og:image` стоит домен `pnemchenko.ru` — поменяйте, если сайт живёт на другом адресе.
- Плевки начинаются через 10 минут бездействия. Время меняется в админке: «Настройки сайта» → «Пасхалка: плевки».
- Проверьте, что сайт открывается по `https://` без предупреждений: без защищённого соединения на телефоне не работает наклон (гироскоп).

## Языки
Сайт готов к двум языкам. Английский включается в админке: «Настройки сайта» → «Английская версия сайта». После этого вверху админки появляется выбор языка, и каждое текстовое поле можно перевести; поля без перевода (и с пустым переводом) показываются по-русски. Подписи интерфейса и реплики головы на английском уже есть.

Какой язык увидит посетитель: адрес с `?lang=en` или `?lang=ru` → его прошлый выбор → домен (`.ru`, `.рф`, `.by`, `.kz` — русский) → язык браузера.

## Шрифт
Arial Narrow есть на Mac и на Windows с Office, и сайт берёт его с компьютера посетителя. Раздавать сам файл Arial Narrow с сайта нельзя — нужна лицензия Monotype. Поэтому там, где шрифта нет (iPhone, Android, Linux), подключается свободный Arimo, сжатый по ширине до тех же пропорций: файлы `assets/fonts/narrow-*.woff2`, лицензия OFL — рядом. Если купите веб-лицензию на Arial Narrow, файлы достаточно подменить.

## Главный экран
- **Раскладка** считается от макета 2000×1414: единица `--u` — 1% ширины экрана, но не больше 1,5% высоты. На широких экранах всё масштабируется от высоты.
- **Голова** занимает столько же места, что в макете: 30,75 единицы от уха до уха (меньше, если окну не хватает высоты). Размер считается по силуэту модели — `_measureSilhouette()` в `js/head.js`; отступы и пределы — в `layout()` в `js/app.js`.
- **Субтитры** — две строки под головой, на телефоне три. Реплика печатается по буквам, 24 буквы в секунду (`CPS` в `js/subtitles.js`), с паузами на знаках препинания; место под всю реплику занято сразу, поэтому текст не прыгает. Строка переносится между предложениями, а не посреди фразы; тире не уезжает в начало строки, короткие слова не остаются в конце (`buildLine()` там же). В каталоге и кейсе реплика стоит вплотную к кружку с головой.
- **Папки** — матовое стекло: закрытая папка ничего не показывает, только размытые пятна работ за стеклом. При наведении (или фокусе с клавиатуры) стенка откидывается, три картинки из разных проектов раздела выглядывают, остальные работы разлетаются по свободному месту экрана — не на голову, не на папки, не на шапку и субтитры.
- **Папки можно таскать.** Положение живёт, пока открыта вкладка; голова комментирует: положили на лицо — возмущается, унесли к самому краю экрана — просит не убирать далеко («другие не увидят мои кэээйсы»). Место «по умолчанию» задаётся в админке.
- **Цвет папки:** нейтральное стекло; свой оттенок задаётся разделу или проекту в админке.
- **Логотип лежит под головой** — отдельным слоем ниже 3D-сцены: когда голову тянут вверх или она подпрыгивает, она перекрывает логотип, а не наоборот. Внутри сайта (каталог, кейс) логотип — часть шапки и стоит над содержимым. Его место считает `layout()` в `js/app.js` (`--logo-w`, `--logo-y`).
- **Телефон и планшет в портрете:** логотип в треть ширины экрана, крупная голова (до 76% ширины — `MOBILE_HEAD` в `js/app.js`), три строки субтитров, лента папок, кнопки в нижней панели. На невысоком экране (телефон с панелями браузера) счётчик проектов под папкой скрывается — место отдаётся голове.
- **Лента папок на телефоне** защёлкивается на папке. Папка, вставшая в центр, раскрывается: три картинки выглядывают из неё, остальные работы встают по бокам головы и выглядывают из-за неё. Касание боковой папки ставит её в центр, касание центральной — открывает раздел. Пока посетитель ленту не трогал, все папки закрыты.

## Загрузка: голова собирается
Процентов и надписи «загрузка» нет. Пока качаются 3D-движок и модель, на месте головы — пара глаз (нарисованы стилями, моргают). Как только модель готова, голова собирается у посетителя на глазах, около четырёх с половиной секунд:

1. глаза → рот изнутри: дёсны с языком, потом зубы — и дважды клацают;
2. очки → септум → каф;
3. мозг — ярко-розовый, мокрый, обклеенный стикерами;
4. кожа нарастает от подбородка к макушке и прячет всё это.

Пока идёт сборка, голова смотрит прямо в экран и на касания не откликается; папки и кнопки работают сразу. Поздоровается она, когда соберётся. Тому, кто на сайте уже был, сборка показывается быстрее — в 1,4 раза. Если страницу открыли сразу в каталоге или кейсе, голова появляется в углу уже собранной.

- Расписание — `INTRO` в начале `js/head.js` (секунды от начала), там же `TEETH_CLIP`: без кожи у зубов видны только коронки.
- Глаза-заглушка — `.eyes` в `css/style.css`; место и размер берутся от рамки головы, цвета сняты с 3D-глаза, поэтому подмена незаметна.
- Мозг и стикеры — `js/brain.js`. Список стикеров — `STICKERS`: радуга, курсор, сердечко, значки 🙄 💅 и два кота, плашки «⌘Z», «Aa», «1px». Значки рисуются системным шрифтом устройства: на Mac и iPhone это их родные эмодзи. Свою картинку (например, фото кота с прозрачным фоном) положите в `assets/brain/` и впишите в список: `{ img: 'assets/brain/cat.png', at: [x, y, z], size: 0.3, roll: 0 }` — белая кайма «наклейки» дорисуется сама.
- При `prefers-reduced-motion` сборки нет: глаза-заглушка стоят неподвижно, голова появляется целиком.

## Каталог
- Папки стоят на дуге: ближние крупнее и слегка не в фокусе, дальние мельче. Прокрутка (колесо, тачпад, стрелки, Home/End) двигает их по дуге и мягко останавливается на проекте.
- При наведении на папку фон страницы плавно принимает цвет проекта с размытой обложкой, интерфейс становится белым. Обложка только затемняет цвет, поэтому текст остаётся читаемым при любой картинке. Фон меняется, когда курсор задержался на папке, — при быстрой прокрутке он не мигает.
- Слева внизу — разделы и список названий: наведение на название подвозит проект.
- На телефоне — лента сверху вниз. Прокрутка защёлкивается на папке: папка встаёт в центр экрана и раскрывается (видны работы проекта), фон принимает стиль проекта. На планшете в альбомной ориентации дуга тоже защёлкивается, а папка в фокусе раскрыта — наведения там нет.
- Геометрия дуги — константы в начале `js/arc.js`: `FW` (размер папки), `RHO` (радиус), `FOCUS` (где стоит папка в фокусе), `G` (во сколько раз соседняя папка крупнее).

## Очки
Очки можно стянуть с лица и унести в любое место экрана — и на главной, и в каталоге, и в кейсе.
- Чем дальше очки от глаз, тем сильнее размыт сайт. Туман наплывает и уходит мягко, с запаздыванием. Поверх размытия — лёгкое зерно, как у матового стекла (`.veil::after` в `css/style.css`).
- Сами очки остаются резкими: они рисуются отдельным слоем поверх размытия.
- Снятые очки всегда поверх головы: если водить ими перед лицом, они не проваливаются в нос и щёки. Пока очки на носу, дужки, как и положено, уходят за уши (`GLASSES_ON_TOP` в `js/head.js`).
- В линзах размытия нет: отверстия в тумане вырезаны точно по их контуру.
- Отпущенные очки висят на месте 4 секунды, потом голова надевает их сама.
- Настройки: сила размытия — `updateVeil()` в `js/app.js` (9 px), время — `GLASSES_HOLD` в `js/head.js`, скорость наплыва — `_updateGlasses` там же.

## Звук
Кнопка «Звук» включает голос. Пока реплики не записаны, голова «бормочет» короткими звуками в такт субтитрам и пружинит со звуком, когда её тянут. Записанные реплики кладутся в `assets/voice/<id>.mp3`, их id — в `assets/voice/manifest.json`. Тексты и подачу см. в `voice-script.md`.

## Свет и кожа
Текстура головы снята с фотографии и уже содержит мягкий студийный свет. Поэтому по умолчанию включён «фотосвет»: ровная заливка и ключевой свет справа, без плёночной тональной кривой. Все настройки — в `PRESETS` в начале `js/head.js`:
- `hemi` — заливка, `key` — ключевой свет: цвет, яркость, направление.
- `skin.tint` — баланс белого кожи, `skin.hair` — яркость волос и бровей.
- `skin.wrap`, `skin.sheen`, `skin.blush`, `skin.lips`, `skin.hairShine`, `skin.rim`, `skin.photo` — живость кожи и волос (0 выключает эффект).
- `eyes.white`, `eyes.glow`, `eyes.shadow`, `eyes.catch`, `eyes.iris`, `eyes.limbus` — глаза.
- `metal` — оправа и пирсинг, `shadows` — мягкие тени от них на лице.

Второй пресет, `cinema`, — вариант с плёночной кривой ACES. Сравнить: добавьте к адресу `?look=cinema`.

## Взгляд и растягивание
Оба глаза смотрят в одну далёкую точку на линии «переносица → курсор», поэтому зрачки не съезжают к носу. Поворот глаз ограничен (`EYE_YAW`, `EYE_UP`, `EYE_DOWN` в начале `js/head.js`), остальное добирает поворот головы.

За чем следит голова:
- **на компьютере** — за курсором мыши, а при наведении на папку — за папкой;
- **на телефоне** — за пальцем она не следит. Она смотрит на посетителя, на папки, пока их листают (лента на главной, лента каталога), и по наклону телефона. Когда прокрутка остановилась, через пару секунд взгляд возвращается к посетителю.

## Наклон телефона (гироскоп)
Голова поворачивается вслед за наклоном телефона. Браузеры отдают датчик наклона только сайту, открытому по **https** (защищённое соединение): по `http://` или с неработающим сертификатом наклон молча выключен. На Android он включается сам, на iPhone и iPad нужно разрешение — сайт просит его плашкой «Буду следить за наклоном» вверху экрана.

Проверить на телефоне: откройте сайт с `?diag` в адресе (например `https://pnemchenko.ru/?diag`). В углу появится справка: размер экрана и головы, защищено ли соединение, есть ли датчик и приходят ли от него события.

## Оклики: «Эй, ты тут?»
Посетитель затих на главной — голова его окликает: через 7 секунд тишины «Эй, ты тут?», потом раз в 13 секунд ещё две реплики («Можно меня потянуть…», «Куда делся?») — и замолкает, пока посетитель не шевельнётся.
- Тишина считается с последнего действия посетителя или с конца последней реплики головы: она договорила, подождала — и только потом окликает.
- Действие — нажатие, прокрутка, клавиша, настоящее движение мыши, наклон телефона. Пока раскрыта папка или голову тянут, оклики молчат.
- Реплики и их порядок — `REACTIONS.idle` в `js/lines.js` (семь штук, идут по кругу). Когда весь список прозвучал, голова окликает реже: первая реплика — через 14 секунд тишины, потом через 21 — чтобы не надоедать.
- Если поставить плевкам совсем короткую задержку (меньше 12 секунд), первый оклик звучит раньше, чтобы успеть до них.

## Пасхалка: заплёванный экран
Если посетитель долго ничего не делает, голова предупреждает и начинает плевать в экран: надувает щёки, откидывается, «тьфу» — и на «стекле» остаётся клякса с пузырьками и подтёками. Плевки ложатся в случайные места и учащаются, пока не покроют экран; последний — во весь экран. Любое действие (мышь, касание, прокрутка, клавиша) — и всё стекает вниз.
- **Через сколько начинается** — в админке: «Настройки сайта» → «Пасхалка: плевки», в минутах бездействия. Сейчас 10; 0 выключает пасхалку. В содержимом это `spitAfter` в `content/site.json`. Чтобы посмотреть её, не меняя настройку, откройте сайт с `?spit=5` в адресе (здесь — секунды).
- Бездействие — это отсутствие действий посетителя, пока вкладка на виду. Отсчёт идёт с последнего действия или с конца последней реплики головы (едва договорив, она не плюёт). Наклон телефона действием не считается; ролик в кейсе, который сейчас играет, — считается.
- Кляксы — `js/spit.js`: сквозь них страница видна размытой (один слой с `backdrop-filter`, обрезанный по контуру всех клякс), реплики головы остаются поверх и читаются. Движение головы — `spit()` в `js/head.js`, реплики — `spit_*` в `js/lines.js`.
- При `prefers-reduced-motion` пасхалка выключена.

Деформация считается в вершинном шейдере как гладкое поле смещений: кожа, глаза, зубы, очки и пирсинг двигаются одним полем, поэтому голова тянется целиком и внутренности не видны. Каждый щипок — две пружины: узкий слой держит точку под пальцем, широкий «желейный» догоняет с запаздыванием. До четырёх щипков одновременно. Константы `SIG_MIN`, `JELLY`, `R_MAX` — в `js/head.js`.

## Публикация
Сайт статический: сервер ему не нужен, хватит хостинга файлов с HTTPS. Three.js и шрифт лежат внутри сайта — внешних CDN нет.

**Сейчас:** сайт лежит в репозитории GitHub `passhhik/pnemchenko-site` и публикуется GitHub Pages из ветки `main` на домен `pnemchenko.ru` (файл `CNAME`). Любая правка, попавшая в `main`, через минуту-две появляется на сайте — в том числе правки содержимого из админки (кнопка «Опубликовать»). Идёт ли сборка и чем закончилась — видно в репозитории на вкладке Actions («pages build and deployment»); упавшую сборку там же можно перезапустить кнопкой Re-run jobs. HTTPS-сертификат выпускает GitHub: в репозитории Settings → Pages должно стоять «DNS check successful» и включён «Enforce HTTPS».

Дальше, для посетителей и из России, и из Европы, надёжнее один репозиторий и две публикации:
- **`pnemchenko.ru` → Timeweb Cloud, App Platform** (статический сайт из того же репозитория). Быстро и стабильно из России, открывается и из-за рубежа.
- **`.com` → Cloudflare Pages** из того же репозитория: бесплатно, быстро по всему миру. Из России Cloudflare замедлен, поэтому российским контактам давайте адрес `.ru`.

Подробности, цены и шаги — в документе «Публикация сайта — хостинг и домен» в проекте.

Не публикуйте служебные папки `_backup_before_update/`, `_debug/` и `content/backup/`.

Типы файлов при ручной загрузке в хранилище: `.js` — `text/javascript`, `.json` — `application/json`, `.glb` — `model/gltf-binary`, `.mp3` — `audio/mpeg`, `.webp` — `image/webp`, `.woff2` — `font/woff2`.

Модель уже сжата (meshopt, 1,4 МБ). После нового экспорта из Blender сожмите её снова — именно этой командой:
```bash
npx @gltf-transform/cli meshopt assets/head.glb assets/head.glb
```
Не используйте `optimize`: он объединяет узлы и упрощает сетку, а код ищет очки, глаза и части головы по именам узлов.

## Повторный экспорт из Blender
Экспортируются копии объектов с «запечёнными» трансформами под пустышкой `HeadRoot`, детали очков — под `Glasses` (линзы — отдельный объект `Glasses_Lenses`: по нему считаются «окна» в размытии). Настройки: glTF Binary, Y-up, морфы с нормалями, анимации выкл, текстуры WebP 86, вершинные цвета — Active (только `Color.001`). Скрытые объекты не экспортируются — перед экспортом включите видимость очков. Фото-накладка из Blender в glTF не переносится — её повторяет шейдер в `head.js` с `assets/face.jpg` и UV-картой `UV_Photo` (в glTF — `TEXCOORD_1`).

Шея срезана прямо в `Mesh_0` чуть ниже подбородка, срез закрыт «крышкой». Исходный меш до среза — скрытый объект `Mesh_0_backup_neck`, файл до всех правок — `~/Desktop/Untitled_backup_2026-09-26.blend`. Кожа за левым ухом использует отдельные зоны текстуры `Image_Clean_v12` (6 небольших островов на пустых местах атласа) — не затирайте их при перерисовке; прежние UV — в `_debug/flap_uv_blender.json`.

## Доступность
- Ссылка «Сразу к работам» — первой по Tab. Папки — настоящие ссылки; фокус с клавиатуры открывает папку так же, как наведение, а в каталоге подвозит её по дуге.
- Каталог управляется стрелками, Home и End; из кейса Esc возвращает в каталог.
- Субтитры дублируются для скринридеров целой фразой (побуквенная печать — только для глаз); разлетающиеся картинки, размытие, слой очков и глаза-заглушка скрыты от них как декоративные.
- Цвет фона проекта проверяется на контраст с текстом ещё в админке (нужно не меньше 4,5).
- `prefers-reduced-motion`: без полётов и плавной прокрутки, текст появляется сразу, голова при загрузке не собирается по частям, а появляется целиком; ролики не запускаются сами, пасхалка с плевками выключена.
- Кляксы от плевков — декоративный слой: от скринридеров скрыт, клики и касания пропускает, реплики головы остаются над ним.
- Если WebGL недоступен или 3D не загрузилось, папки, каталог и кейсы работают без головы.
- Кнопки на телефоне — 48 px в высоту.
