# Портфолио с интерактивной головой

Белый лист, логотип-подпись, 3D-голова по центру и три папки разделов из матового стекла. При загрузке голова собирается по частям: мозг в стикерах, глаза, рот, очки, пирсинг — и кожа. Она следит за курсором, говорит субтитрами, тянется как резиновая; очки снимаются. Каталог — папки проектов на дуге, фон при наведении окрашивается в стиль проекта. Кейсы собираются из блоков в админке и публикуются на сайт одной кнопкой. Если посетитель затих, голова его окликает, а если «залип» надолго — плевок за плевком заплёвывает экран.

## Запуск на своём компьютере
Сайту нужен локальный сервер: двойной клик по `index.html` не сработает.

- **Проще всего:** двойной клик по `start.command` в папке сайта. Откроется окно Терминала и браузер с админкой. Если macOS не даёт запустить файл — правый клик → «Открыть». Если пишет «нет прав», один раз выполните в Терминале `chmod +x ~/Desktop/portfolio-head/start.command`.
- **Вручную:**
  ```bash
  cd ~/Desktop/portfolio-head
  python3 -m http.server 8765
  ```
  Сайт — http://localhost:8765, админка — http://localhost:8765/admin/

## Админка
Адрес: `…/admin/` — и на компьютере, и на опубликованном сайте. Слева — проекты (порядок в списке = порядок в каталоге; перетаскивайте или двигайте стрелками). В середине — форма. Справа — живой предпросмотр: кейс, папка в каталоге, вид с телефона.

Работать можно тремя способами, их можно сочетать.

**1. С сайтом — правки публикуются прямо из админки.** Нажмите «Подключить сайт» и один раз вставьте токен доступа к репозиторию на GitHub (как его получить — ниже). Дальше:
- содержимое открывается прямо с сайта, самое свежее;
- кнопка «Опубликовать» (или ⌘S) отправляет тексты и новые картинки на сайт. Через минуту-две админка напишет «Опубликовано» — правки уже видны посетителям;
- работает в любом браузере и с любого компьютера.

**2. С папкой сайта на компьютере** (Chrome или Edge). «Выбрать папку сайта» → укажите `portfolio-head` и разрешите изменение файлов. «Сохранить» (⌘S) записывает `content/site.json`, `content/projects.json` и новые картинки прямо в папку; прежняя версия содержимого уходит в `content/backup/` (хранятся последние 12 сохранений). Если к папке подключить ещё и сайт, рядом появится «Опубликовать»: она сохраняет в папку и отправляет на сайт содержимое со всеми картинками, которых там ещё нет. Так удобно готовить кейс черновиком и выкладывать, когда готов.

**3. Без сайта и без папки** — изменения скачиваются архивом, который нужно распаковать в папку сайта.

### Как получить токен для «Подключить сайт»
Токен — это ключ, по которому админка имеет право менять файлы в репозитории сайта. Создаётся один раз, занимает две минуты:
1. На GitHub: фото профиля → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Прямая ссылка есть в окне «Подключить сайт».
2. Token name — любое, например «Админка портфолио». Expiration — срок действия; когда он выйдет, админка попросит новый токен.
3. Repository access → Only select repositories → `pnemchenko-site`.
4. Permissions → Repository permissions → Contents → Read and write. Остальное не трогайте.
5. Generate token → скопируйте строку `github_pat_…` и вставьте в админку.

Что важно знать:
- Токен хранится только в вашем браузере и уходит только на `api.github.com`. Он даёт доступ к одному репозиторию. Кнопка «отключить» в шапке админки стирает его из браузера; отозвать совсем — на той же странице GitHub.
- Подключить сайт можно только по защищённому адресу: `https://…/admin/` или с этого компьютера (`start.command` → `localhost`). По `http://` админка токен не примет.
- Если на сайте за это время появилась другая версия содержимого (правили с другого компьютера), админка спросит, прежде чем заменить её вашей.
- После публикации хостинг сам забирает правки из репозитория и выкладывает их — обычно за минуту-две. Админка, открытая на самом сайте (`https://pnemchenko.ru/admin/`), пишет «Опубликовано», когда сайт уже отдаёт новую версию: она сверяет файл на сайте с отправленным. Пишете большой кейс — публикуйте, когда готов кусок, а не каждую запятую.
- После «Опубликовано» на сайте всё ещё старое? Обновите страницу (⌘⇧R): браузер мог держать прежние файлы.
- Если админка пишет «Отправлено», а правок на сайте нет дольше десяти минут — откройте панель хостинга (Timeweb Cloud → приложение → вкладка «Деплой»): там видно, собран ли последний коммит, и сборку можно запустить заново.
- Админка, открытая с компьютера (`start.command` → `localhost`), сайт спросить не может и узнаёт о публикации у GitHub; если GitHub Pages выключен, она напишет «Отправлено» — правки всё равно дойдут.

Что умеет:
- **Основное:** название, раздел, год, короткое описание, роль, клиент, команда, срок, теги, адрес страницы, переключатель «На сайте» (черновики видны только в админке).
- **Папка и фон:** обложка, наклейка на папке, цвет фона проекта (сразу показывает, читается ли на нём текст), цвет самой папки, работы проекта.
- **Результаты:** цифры и «суть в трёх абзацах» — задача, что сделал, результат.
- **Блоки:** текст, картинка, галерея, цифры, цитата, шаги, «до / после», видео, палитра. Порядок меняется перетаскиванием. У картинки есть ширина (в колонку текста, широкая, во весь экран) и подложка; у блока — реплика головы, которую она скажет, когда блок доедет до середины экрана.
- **Настройки сайта:** имя, роль, почта и Telegram, резюме, логотип, разделы, английская версия. Папки на главной расставляются мышью прямо в предпросмотре.
- **Реплики головы** (кнопка под «Настройками сайта»): все её фразы списком «когда звучит → что говорит», по группам. Текст можно переписать; пустое поле — в этой ситуации голова промолчит; стрелка возвращает исходный текст. В содержимом хранятся только ваши правки (`lines` в `content/site.json`), остальное берётся из `js/lines.js`. Английские реплики правятся так же, после переключения языка вверху админки.
- **Картинки** при загрузке уменьшаются (до 2400 px по длинной стороне; работы для папок — до 900, наклейка — до 480) и сохраняются в WebP в `assets/cases/<адрес-проекта>/`. Прозрачность определяется сама («без фона»). Размеры картинки запоминаются: страница кейса заранее оставляет под неё место и не прыгает, пока та грузится. Как готовить материалы — в документе «Как готовить кейсы» в проекте.
- Внизу формы — **проверка перед публикацией**: чего не хватает кейсу.

В Safari и Firefox нет доступа к папкам на компьютере: там подключайте сайт (способ 1) или скачивайте изменения архивом.

Удалённые в админке картинки и проекты из папки и из репозитория не стираются — лишние файлы в `assets/cases/` можно убрать вручную.

## Скелет кейса
Нанимающий читает по диагонали, поэтому кейс устроен «от итога к деталям»:

1. **Шапка на цвете проекта:** название, одна фраза о сути, факты (год, роль, клиент, команда, срок), обложка.
2. **Результаты в цифрах** — крупно, первым экраном белого листа.
3. **Суть в трёх абзацах:** задача → что сделал → результат.
4. **Блоки** — подробности для тех, кто дочитал: контекст и проблема → решение крупно → процесс по шагам → детали галереей → отзыв.
5. **Теги, контакт, следующий проект.**

Новый проект в админке создаётся с этим скелетом; пустые блоки на сайте не показываются.

## Перед публикацией
- Впишите в «Настройках сайта» почту и Telegram: без них в конце кейса нет кнопки «Написать».
- Загрузите резюме: пока файла нет, кнопка CV скрыта.
- В `index.html` в строке `og:image` стоит домен `pnemchenko.ru` — поменяйте, если сайт живёт на другом адресе.
- Плевки начинаются через 10 минут бездействия. Время меняется в админке: «Настройки сайта» → «Пасхалка: плевки».
- Проверьте, что сайт открывается по `https://` без предупреждений: без защищённого соединения на телефоне не работает наклон (гироскоп).
- Один раз настройте хостинг: сжатие, заголовки защиты и лимит запросов — см. «Защита».

## Языки
Сайт готов к двум языкам. Английский включается в админке: «Настройки сайта» → «Английская версия сайта». После этого вверху админки появляется выбор языка, и каждое текстовое поле можно перевести; поля без перевода (и с пустым переводом) показываются по-русски. Подписи интерфейса и реплики головы на английском уже есть.

Какой язык увидит посетитель: адрес с `?lang=en` или `?lang=ru` → его прошлый выбор → домен (`.ru`, `.рф`, `.by`, `.kz` — русский) → язык браузера.

## Шрифт
Arial Narrow есть на Mac и на Windows с Office, и сайт берёт его с компьютера посетителя. Раздавать сам файл Arial Narrow с сайта нельзя — нужна лицензия Monotype. Поэтому там, где шрифта нет (iPhone, Android, Linux), подключается свободный Arimo, сжатый по ширине до тех же пропорций: файлы `assets/fonts/narrow-*.woff2`, лицензия OFL — рядом. Если купите веб-лицензию на Arial Narrow, файлы достаточно подменить.

## Главный экран
- **Раскладка** считается от макета 2000×1414: единица `--u` — 1% ширины экрана, но не больше 1,5% высоты. На широких экранах всё масштабируется от высоты.
- **Голова** занимает столько же места, что в макете: 30,75 единицы от уха до уха (меньше, если окну не хватает высоты). Размер считается по силуэту модели — `_measureSilhouette()` в `js/head.js`; отступы и пределы — в `layout()` в `js/app.js`.
- **Субтитры** — две строки под головой, на телефоне три. Реплика печатается по буквам, 24 буквы в секунду (`CPS` в `js/subtitles.js`), с паузами на знаках препинания; место под всю реплику занято сразу, поэтому текст не прыгает. Строка переносится между предложениями, а не посреди фразы; тире не уезжает в начало строки, короткие слова не остаются в конце (`buildLine()` там же). В каталоге и кейсе реплика стоит вплотную к кружку с головой.
- **Папки** — матовое стекло: закрытая папка ничего не показывает, только размытые пятна работ за стеклом. При наведении (или фокусе с клавиатуры) стенка откидывается, три картинки из разных проектов раздела выглядывают, остальные работы разлетаются по свободному месту экрана — не на голову, не на папки, не на шапку и субтитры.
- **Папки можно таскать.** Положение живёт, пока открыта вкладка; голова комментирует: положили на лицо — возмущается, унесли к самому краю экрана — просит не убирать далеко («другие не увидят мои кэээйсы»). Место «по умолчанию» задаётся в админке.
- **Цвет папки:** нейтральное стекло; свой оттенок задаётся разделу или проекту в админке.
- **Логотип лежит под головой** — отдельным слоем ниже 3D-сцены: когда голову тянут вверх или она подпрыгивает, она перекрывает логотип, а не наоборот. Внутри сайта (каталог, кейс) логотип — часть шапки и стоит над содержимым. Его место считает `layout()` в `js/app.js` (`--logo-w`, `--logo-y`).
- **Телефон и планшет в портрете — чистый экран:** логотип (56% ширины экрана, на планшете не шире 480 px — `CLEAN_LOGO`, `CLEAN_LOGO_MAX`), голова, три строки реплики и кнопки в нижней панели. Папок разделов здесь нет: в разделы посетитель попадает через «Все работы», а вторая реплика приветствия так и говорит — и голова в этот момент смотрит на кнопку, а та один раз «кивает». Голова — до 72% ширины экрана, на вытянутых экранах до 78% (`CLEAN_HEAD`); свободная высота остаётся воздухом, чуть больше над головой (`CLEAN_DROP`). Реплика стоит под подбородком с запасом: когда голова говорит, челюсть опускается. Всё это — ветка `clean` в `layout()` в `js/app.js`.
- **Кнопки на телефоне:** «Все работы» залита и шире — это главное действие; CV и «Звук» — контуром. На нажатие кнопка отвечает лёгким сжатием.
- **Где показывать папки на главной** — в админке: «Настройки сайта» → «Разделы» → «Папки разделов на главной»: «На компьютере — да, на телефоне — нет» (так по умолчанию), «Везде», «Нигде». В содержимом это `heroFolders` в `content/site.json` (`all`, `none`; ключа нет — по умолчанию); решает `heroFolders()` в `js/content.js`. Там, где папок нет, они и не строятся — и картинки работ для них не качаются.
- **Если папки на телефоне включить («Везде»)**, они встают лентой над кнопками: логотип в треть ширины экрана, голова до 76% (`MOBILE_HEAD`), лента защёлкивается на папке. Папка, вставшая в центр, раскрывается: три картинки выглядывают из неё, остальные работы встают по бокам головы. Касание боковой папки ставит её в центр, касание центральной — открывает раздел. На невысоком экране счётчик проектов под папкой скрывается — место отдаётся голове.
- **Стекло папок на телефоне и планшете** устроено иначе, чем на компьютере, а выглядит так же. На компьютере стекло размывает всё, что под ним (`backdrop-filter`). На телефоне это самый дорогой эффект — лента с ним прокручивается рывками, а в Safari такое стекло ещё и мигает, когда рядом что-то меняется (например, печатается реплика). Поэтому там под стеклом лежит размытый двойник нутра папки — задняя стенка и те же работы (`.gf-ghost`: разметка в `js/folders.js`, стили рядом с `.gf-front`), а настоящие работы видны только там, где стекла нет.

## Загрузка: голова собирается
Процентов и надписи «загрузка» нет. Пока качается 3D-движок, на месте головы — розовое размытое пятно. Движок готов — пятно сменяет мозг: ярко-розовый, мокрый, обклеенный стикерами. Он висит и покачивается, пока качается модель, — он и есть «загрузка». Модель пришла — голова собирается вокруг него, примерно за две с половиной секунды:

1. глаза;
2. рот изнутри: дёсны с языком, верхние зубы, нижние — и один раз клацают;
3. очки надеваются спереди → септум → каф;
4. кожа нарастает от подбородка к макушке и прячет мозг; голова при этом чуть подплывает к зрителю.

Пока идёт сборка, голова смотрит прямо в экран и на касания не откликается; папки и кнопки работают сразу. Поздоровается она, когда соберётся. Тому, кто на сайте уже был, сборка показывается быстрее — в 1,4 раза. Если страницу открыли сразу в каталоге или кейсе, голова появляется в углу уже собранной.

- Расписание — `INTRO` в начале `js/head.js`: секунды от момента, когда модель готова; `brainMin` — сколько мозг самое малое висит один. Там же `INTRO_ZOOM` (с какого размера голова «подплывает») и `TEETH_CLIP`: без кожи у зубов видны только коронки.
- Пятно-заглушка — `.brainph` в `css/style.css`; место и размер берутся от рамки головы.
- Мозг и стикеры — `js/brain.js`. Список стикеров — `STICKERS`: радуга, курсор, сердечко, значки 🙄 💅 и два кота, плашки «⌘Z», «Aa», «1px». Значки рисуются системным шрифтом устройства: на Mac и iPhone это их родные эмодзи. Свою картинку (например, фото кота с прозрачным фоном) положите в `assets/brain/` и впишите в список: `{ img: 'assets/brain/cat.png', at: [x, y, z], size: 0.3, roll: 0 }` — белая кайма «наклейки» дорисуется сама.
- При `prefers-reduced-motion` сборки нет: пятно стоит неподвижно, голова появляется целиком.
- **Порядок загрузки — по очереди.** Сначала интерфейс и 3D-движок (он нужен мозгу), и только когда движок скачан — модель и её загрузчики (`boot()` в `js/app.js`, `fetched()` в `js/model.js`). Если качать всё сразу, тяжёлая модель делит канал с движком, и на мобильной сети мозг появляется вдвое позже.
- **Телефону — своя модель.** `assets/head-m.glb`: те же сетки, текстура кожи 1024² вместо 2048² — на экране телефона разницы не видно, а файл на четверть меньше. Обе версии лежат ещё и сжатыми (`.glb.gz`): сервер модели не сжимает, поэтому сайт качает сжатую и распаковывает сам; браузер, который этого не умеет (Safari старше 16.4), берёт обычную. Какую версию брать, решает `js/model.js` (узкий экран с касанием — телефонную). Сравнить глазами: `?model=full` и `?model=phone` в адресе.

## Каталог
- Папки стоят на дуге: ближние крупнее и слегка не в фокусе, дальние мельче. Прокрутка (колесо, тачпад, стрелки, Home/End) двигает их по дуге и мягко останавливается на проекте.
- При наведении на папку фон страницы плавно принимает цвет проекта с размытой обложкой, интерфейс становится белым. Обложка только затемняет цвет, поэтому текст остаётся читаемым при любой картинке. Фон меняется, когда курсор задержался на папке, — при быстрой прокрутке он не мигает.
- Слева внизу — разделы и список названий: наведение на название подвозит проект.
- На телефоне — лента сверху вниз. Прокрутка защёлкивается на папке: папка встаёт в центр экрана и раскрывается (видны работы проекта), фон принимает стиль проекта. На планшете в альбомной ориентации дуга тоже защёлкивается, а папка в фокусе раскрыта — наведения там нет.
- Геометрия дуги — константы в начале `js/arc.js`: `FW` (размер папки), `RHO` (радиус), `FOCUS` (где стоит папка в фокусе), `G` (во сколько раз соседняя папка крупнее).

## Очки
Очки можно стянуть с лица и унести в любое место экрана — и на главной, и в каталоге, и в кейсе.
- Чем дальше очки от глаз, тем сильнее размыт сайт. Туман наплывает и уходит мягко, с запаздыванием. Поверх размытия — лёгкое зерно, как у матового стекла (`.veil::after` в `css/style.css`).
- Сами очки остаются резкими: они рисуются отдельным слоем поверх размытия.
- Снятые очки всегда поверх головы: если водить ими перед лицом, они не проваливаются в нос и щёки. Пока очки на носу, дужки, как и положено, уходят за уши (`GLASSES_ON_TOP` в `js/head.js`).
- В линзах размытия нет: отверстия в тумане вырезаны точно по их контуру.
- Отпущенные очки висят на месте 4 секунды, потом голова надевает их сама.
- Настройки: сила размытия — `updateVeil()` в `js/app.js` (9 px), время — `GLASSES_HOLD` в `js/head.js`, скорость наплыва — `_updateGlasses` там же.

## Звук
Кнопка «Звук» включает голос. Пока реплики не записаны, голова «бормочет» короткими звуками в такт субтитрам и пружинит со звуком, когда её тянут. Записанные реплики кладутся в `assets/voice/<id>.mp3`, их id — в `assets/voice/manifest.json`. Тексты и подачу см. в `voice-script.md`.

## Свет и кожа
Текстура головы снята с фотографии и уже содержит мягкий студийный свет. Поэтому по умолчанию включён «фотосвет»: ровная заливка и ключевой свет справа, без плёночной тональной кривой. Все настройки — в `PRESETS` в начале `js/head.js`:
- `hemi` — заливка, `key` — ключевой свет: цвет, яркость, направление.
- `skin.tint` — баланс белого кожи, `skin.hair` — яркость волос и бровей.
- `skin.wrap`, `skin.sheen`, `skin.blush`, `skin.lips`, `skin.hairShine`, `skin.rim`, `skin.photo` — живость кожи и волос (0 выключает эффект).
- `eyes.white`, `eyes.glow`, `eyes.shadow`, `eyes.catch`, `eyes.iris`, `eyes.limbus` — глаза.
- `metal` — оправа и пирсинг, `shadows` — мягкие тени от них на лице.

Второй пресет, `cinema`, — вариант с плёночной кривой ACES. Сравнить: добавьте к адресу `?look=cinema`.

## Взгляд и растягивание
Оба глаза смотрят в одну далёкую точку на линии «переносица → курсор», поэтому зрачки не съезжают к носу. Поворот глаз ограничен (`EYE_YAW`, `EYE_UP`, `EYE_DOWN` в начале `js/head.js`), остальное добирает поворот головы.

За чем следит голова:
- **на компьютере** — за курсором мыши, а при наведении на папку — за папкой;
- **на телефоне** — за пальцем она не следит. Она смотрит на посетителя, на папки, пока их листают (лента на главной, лента каталога), а при наклоне телефона ведёт себя как объёмный предмет в руке (см. ниже). Когда прокрутка остановилась, через пару секунд взгляд возвращается к посетителю.

Деформация считается в вершинном шейдере как гладкое поле смещений: кожа, глаза, зубы, очки и пирсинг двигаются одним полем, поэтому голова тянется целиком и внутренности не видны. Каждый щипок — две пружины: узкий слой держит точку под пальцем, широкий «желейный» догоняет с запаздыванием. До четырёх щипков одновременно. Константы `SIG_MIN`, `JELLY`, `R_MAX` — в `js/head.js`.

## Наклон телефона: эффект присутствия
Телефон — как коробка с головой внутри, а посетитель стоит на месте. Что происходит, когда телефон крутят в руке:
- **Объём.** Повернули телефон — голову видно чуть сбоку, как любой объёмный предмет, который вертят в руке.
- **Доворот.** За полсекунды голова поворачивается обратно к посетителю — не до конца, как живой человек: остальное добирают глаза.
- **Взгляд.** Глаза всё это время смотрят в камеру. На плоском экране взгляд «в камеру» — это взгляд на зрителя под любым углом, поэтому зрительный контакт не рвётся.
- **Крен.** Телефон завалили набок — голова остаётся вертикальной (до ~20°). Если телефон лежит на столе или повёрнут набок целиком (читают лёжа), крен не трогается.
- **Логотип неподвижен.** При наклоне двигается только голова; логотип стоит на месте (раньше он смещался «в глубине» — Павлу показалось лишним).
- **В углу — без наклона.** В каталоге и кейсе, где голова свёрнута в кружок, эффект плавно гаснет (за полсекунды) и так же плавно возвращается на главной.
- **Новая поза.** Телефон замер в новом положении (человек пересел, лёг) — за несколько секунд оно становится «прямо перед зрителем», голова снова смотрит ровно.

Сила эффекта — `TILT` в начале `js/head.js`: `depth` (объём: 0 — плоская картинка, 1 — как настоящий предмет; отрицательное значение переворачивает направление), `follow` (доворот), `roll` (крен). Подбирать удобно на самом телефоне: адрес с `?diag` показывает три ползунка, значения видны в справке.

Браузеры отдают датчик наклона только сайту, открытому по **https** (защищённое соединение): по `http://` или с неработающим сертификатом наклон молча выключен. На Android он включается сам, на iPhone и iPad нужно разрешение — сайт просит его плашкой «Буду следить за наклоном». Плашка появляется сразу, вместе со страницей (голова ей не нужна), стоит над кнопками, и раскладка оставляет под неё место; разрешить наклон можно, ещё пока голова собирается. Если плашку не тронули, через 20 секунд после приветствия она уходит, а место плавно возвращается голове (`setupTilt()`, `showTip()` в `js/app.js`). При настройке «меньше движения» наклон выключен.

Тот, кто уже разрешал наклон, плашку обычно не видит. Safari помнит разрешение, пока его не закрыли, и отвечает на вопрос сайта молча, без касания (`quietTilt()`): помнит — наклон работает с первой секунды. Забыл (Safari перезапускали) — плашка появляется снова, тоже сразу; пока она на экране, разрешение спросит и нажатие на голову или пустое место (`armTiltTap()`), а кнопки и ссылки — нет. Отказ в системном окне и закрытая крестиком плашка запоминаются: больше сайт не спрашивает (кроме режима `?diag`).

Проверить на телефоне: откройте сайт с `?diag` в адресе (например `https://pnemchenko.ru/?diag`). Появится справка: размер экрана и головы, защищено ли соединение, что браузер ответил на запрос разрешения, углы датчика и поворот головы. Плашка «Включить» в этом режиме не прячется — наклон можно включить заново, даже если раньше от него отказались.

## Оклики: «Эй, ты тут?»
Посетитель затих на главной — голова его окликает: через 7 секунд тишины «Эй, ты тут?», потом раз в 13 секунд ещё две реплики («Можно меня потянуть…», «Куда делся?») — и замолкает, пока посетитель не шевельнётся.
- Тишина считается с последнего действия посетителя или с конца последней реплики головы: она договорила, подождала — и только потом окликает.
- Действие — нажатие, прокрутка, клавиша, настоящее движение мыши, наклон телефона. Пока раскрыта папка или голову тянут, оклики молчат.
- Реплики и их порядок — `REACTIONS.idle` в `js/lines.js` (семь штук, идут по кругу). Там, где папок на главной нет, вместо подсказки «Папки можно таскать» звучит «Кейсы сами себя не посмотрят. Жми „Все работы“» — список `REACTIONS.idleClean`. Когда весь список прозвучал, голова окликает реже: первая реплика — через 14 секунд тишины, потом через 21 — чтобы не надоедать.
- Если поставить плевкам совсем короткую задержку (меньше 12 секунд), первый оклик звучит раньше, чтобы успеть до них.

## Пасхалка: заплёванный экран
Если посетитель долго ничего не делает, голова предупреждает и начинает плевать в экран. Она шкодничает, а не строчит очередями: присмотрелась к чистому месту, набрала в щёки, «тьфу» — проводила плевок взглядом и глянула на посетителя. Пауза две-четыре секунды — и следующий. Стекло заполняется за десяток-полтора плевков, примерно за минуту; по дороге голова это комментирует. Любое действие (мышь, касание, прокрутка, клавиша) — и всё стекает вниз.

Сам плевок — прозрачная вязкая слюна, а не картинка: видно, как он летит от рта и растёт, шлёпается о «стекло», расплющивается, выбрасывает нити с каплями на концах и потом долго стекает подтёками. Внутри — пузырьки и островки пены, сквозь толстые места страница видна слегка размытой.

- **Через сколько начинается** — в админке: «Настройки сайта» → «Пасхалка: плевки», в минутах бездействия. Сейчас 10; 0 выключает пасхалку. В содержимом это `spitAfter` в `content/site.json`. Чтобы посмотреть её, не меняя настройку, откройте сайт с `?spit=5` в адресе (здесь — секунды).
- Бездействие — это отсутствие действий посетителя, пока вкладка на виду. Отсчёт идёт с последнего действия или с конца последней реплики головы (едва договорив, она не плюёт). Наклон телефона действием не считается; ролик в кейсе, который сейчас играет, — считается.
- **Темп** — в `js/app.js`: `spitAim()`, `spitFire()`, `onSpit()` (паузы между плевками), `SPIT_SAY` (реплики после каждого второго плевка) и `SPIT_ALMOST` (когда звучит «Ещё чуть-чуть»). Куда лететь следующему и когда стекло «заплёвано» — `next()` в `js/spit.js`.
- **Слюна** — `js/spit.js`. Всё мокрое складывается из мягких пятен в «поле плотности» на отдельном холсте WebGL: где сумма выше порога, там жидкость, поэтому соседние капли сливаются перемычками. По полю шейдер считает наклон поверхности и рисует блики, тёмную кромку, пузырьки и тень. Форма кляксы, нити, брызги и подтёки — `_hit()` и `_step()`, вид жидкости — шейдер `FS_SHADE`. Холст перерисовывается, только пока что-то движется.
- Движение головы — `spit()` в `js/head.js`, реплики — `spit_*` в `js/lines.js` (их можно переписать в админке).
- Нужен WebGL2 (все браузеры с 2021–2022 года). Где его нет, пасхалка просто не включается. При `prefers-reduced-motion` она выключена.

## Публикация
Сайт статический: сервер ему не нужен, хватит хостинга файлов с HTTPS. Three.js и шрифт лежат внутри сайта — внешних CDN нет.

**Сейчас:** файлы лежат в репозитории GitHub `passhhik/pnemchenko-site`, ветка `main`. Раздаёт их **Timeweb Cloud, App Platform** (приложение «HTML/CSS/JS» из этого репозитория, регион Москва) на `https://pnemchenko.ru` и `www`; `http://` сам переходит на `https://`. Любая правка, попавшая в `main`, через минуту-две появляется на сайте — в том числе правки содержимого из админки (кнопка «Опубликовать»). Собран ли последний коммит — видно в панели Timeweb на вкладке «Деплой»; там же можно запустить сборку заново или откатиться к прошлому коммиту. Технический адрес приложения — `passhhik-pnemchenko-site-844e.twc1.net`: по нему удобно проверять.

Файл `CNAME` в репозитории не удаляйте: по нему админка узнаёт адрес сайта.

Для посетителей из-за рубежа позже можно добавить вторую публикацию того же репозитория — домен `.com` на Cloudflare Pages: бесплатно и быстро по всему миру (из России Cloudflare замедлен, поэтому российским контактам — адрес `.ru`). Подробности, цены и шаги — в документе «Публикация сайта — хостинг и домен» в проекте.

Не публикуйте служебные папки `_backup_before_update/`, `_debug/` и `content/backup/`.

Типы файлов при ручной загрузке в хранилище: `.js` — `text/javascript`, `.json` — `application/json`, `.glb` — `model/gltf-binary`, `.mp3` — `audio/mpeg`, `.webp` — `image/webp`, `.woff2` — `font/woff2`.

Модель уже сжата (meshopt, 1,4 МБ). После нового экспорта из Blender — два шага, оба обязательны:
```bash
npx @gltf-transform/cli meshopt assets/head.glb assets/head.glb
python3 tools/models.py
```
Первая команда сжимает сетки. Не используйте вместо неё `optimize`: он объединяет узлы и упрощает сетку, а код ищет очки, глаза и части головы по именам узлов. Вторая собирает из `head.glb` телефонную версию и сжатые копии (`head-m.glb`, `head.glb.gz`, `head-m.glb.gz`). **Без второго шага сайт продолжит показывать прежнюю голову:** он берёт сжатые копии, а они остались от старой модели.

## Скорость
- **Голова подстраивается под устройство.** Плотность пикселей 3D-сцены (не выше 1,75 от экранной) снижается, если кадр рисуется дольше 25 мс, и возвращается, когда появился запас; попытку, которая не помогла, сцена запоминает и не повторяет. Пока голова спокойна — её не трогают, она молчит, телефон не наклоняют, — она рисуется вдвое реже, 30 раз в секунду: процессор и батарея остаются странице. Настройки — `this.q`, `_adapt()` и `_pace()` в `js/head.js`.
- **Без рывка при появлении:** шейдеры головы собираются до первого кадра, а холст не пересоздаётся, пока голова улетает в угол.
- **Фон «в стиле проекта»** — обложка, заранее уменьшенная и размытая на крошечном холсте (`softImage()` в `js/theme.js`). Размывать слой во весь экран стилями было заметно дороже, особенно на телефонах.
- **Каталог:** стили папок на дуге пишутся только при изменении; у папок не в фокусе вместо «матового стекла» — простая заливка.
- **Кейс:** картинки грузятся по мере прокрутки, место под них занято заранее — страница не прыгает. Ролики играют, только пока видны.
- **Субтитры без лишних слоёв.** Буквы проявляются через `visibility` и цвет, реплика гаснет прозрачностью всего блока. Прежде у каждой буквы был свой переход прозрачности — браузер заводил под него отдельный слой, два десятка в секунду.
- **Слой для снятых очков** (второй холст) создаётся, когда голова собралась и секунду молчит, — а не посреди сборки, как раньше (`_warmOverlay()` в `js/head.js`).
- **Первый заход на телефоне** — около 54 файлов и 2,3 МБ без сжатия на хостинге (было 80 файлов и 3,4 МБ): код и тексты 1,2 МБ, модель 0,7 МБ, картинки первых папок каталога 0,3 МБ — они подгружаются, когда главная уже готова. На компьютере — около 80 файлов и 3,1 МБ: там есть папки с работами, а модель полная. Со сжатием на хостинге код и тексты ужимаются до 0,35 МБ — мозг и голова появляются заметно раньше.
- **Проверить на своём устройстве:** адрес с `?diag` показывает, сколько кадров в секунду рисует голова и с какой плотностью, сколько файлов и мегабайт пришло по сети, сжимает ли их сервер, сколько браузер взял из своей памяти и этапы загрузки в секундах: страница, движок, мозг, модель, голова собрана.

## Защита
Сайт — набор файлов: на нём нет сервера, базы и форм, взламывать нечего. Что сделано в коде:
- **Политика содержимого (CSP)** — первая строка в `<head>` у `index.html` и `admin/index.html`. Странице разрешены скрипты, стили, шрифты, картинки и запросы только со своего адреса (админке — ещё к `api.github.com`). Чужой или вставленный в страницу скрипт браузер не выполнит. **Подключаете внешний сервис** — счётчик, ролик с YouTube или Vimeo, шрифты — его адрес нужно дописать в эту строку, иначе браузер молча его заблокирует.
- **Сторонних скриптов нет:** Three.js и шрифт лежат на сайте, cookie сайт не ставит.
- **Админка** без токена ничего изменить не может. Токен хранится только в браузере владельца, даёт доступ к одному репозиторию и уходит только на `api.github.com`. Страница закрыта от поисковиков (`robots.txt` и `noindex`).

Что настраивается один раз в панели хостинга (Timeweb Cloud → приложение → «Настройки» → «Настройки веб-сервера»; после «Сохранить» сайт пересоберётся сам):
- **Сжатие:** `gzip` и `zstd` — код и тексты передаются в три-четыре раза компактнее (1,2 МБ → 0,35 МБ на первом заходе).
- **HTTP-заголовки** (тип `set`):

  | Имя | Значение | Зачем |
  |---|---|---|
  | `Strict-Transport-Security` | `max-age=2592000` | Браузер месяц ходит на сайт только по https. Через пару месяцев можно поставить год: `31536000` |
  | `X-Content-Type-Options` | `nosniff` | Файл выполняется только как тот тип, каким его отдали |
  | `X-Frame-Options` | `SAMEORIGIN` | Сайт нельзя встроить в чужую страницу (предпросмотр в админке работает: он на том же адресе) |
  | `Referrer-Policy` | `strict-origin-when-cross-origin` | Другим сайтам не уходит полный адрес страницы |
  | `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=(), usb=()` | Странице заведомо не нужны камера, микрофон и геолокация |
  | `Cache-Control` | `public, max-age=300` | Браузер пять минут не переспрашивает файлы, потом сверяет их с сайтом |

- **Лимит входящих запросов** («Настройки» приложения). Запросы платные (4,95 ₽ за 10 000), и лимит — это потолок расходов: когда он исчерпан, Timeweb останавливает приложение и перестаёт списывать деньги. Сайт при этом не открывается, пока лимит не поднять, — поэтому ставьте его с запасом.

Чего защитить нельзя: код страницы, модель головы и картинки браузер скачивает, чтобы показать, — значит, их может сохранить любой посетитель. Скрыть можно только историю правок, сделав репозиторий закрытым (админка к этому готова; перед этим проверьте, что Timeweb продолжает забирать коммиты).

Проверить заголовки после настройки: securityheaders.com → адрес сайта.

## Повторный экспорт из Blender
Экспортируются копии объектов с «запечёнными» трансформами под пустышкой `HeadRoot`, детали очков — под `Glasses` (линзы — отдельный объект `Glasses_Lenses`: по нему считаются «окна» в размытии). Настройки: glTF Binary, Y-up, морфы с нормалями, анимации выкл, текстуры WebP 86, вершинные цвета — Active (только `Color.001`). Скрытые объекты не экспортируются — перед экспортом включите видимость очков. Фото-накладка из Blender в glTF не переносится — её повторяет шейдер в `head.js` с `assets/face.jpg` и UV-картой `UV_Photo` (в glTF — `TEXCOORD_1`).

Шея срезана прямо в `Mesh_0` чуть ниже подбородка, срез закрыт «крышкой». Исходный меш до среза — скрытый объект `Mesh_0_backup_neck`, файл до всех правок — `~/Desktop/Untitled_backup_2026-09-26.blend`. Кожа за левым ухом использует отдельные зоны текстуры `Image_Clean_v12` (6 небольших островов на пустых местах атласа) — не затирайте их при перерисовке; прежние UV — в `_debug/flap_uv_blender.json`.

## Доступность
- Ссылка «Сразу к работам» — первой по Tab. Папки — настоящие ссылки; фокус с клавиатуры открывает папку так же, как наведение, а в каталоге подвозит её по дуге.
- Каталог управляется стрелками, Home и End; из кейса Esc возвращает в каталог.
- Субтитры дублируются для скринридеров целой фразой (побуквенная печать — только для глаз); разлетающиеся картинки, размытие, слой очков и пятно-заглушка скрыты от них как декоративные.
- Цвет фона проекта проверяется на контраст с текстом ещё в админке (нужно не меньше 4,5).
- `prefers-reduced-motion`: без полётов и плавной прокрутки, текст появляется сразу, голова при загрузке не собирается по частям, а появляется целиком; ролики не запускаются сами, пасхалка с плевками выключена.
- Слюна от плевков — декоративный слой: от скринридеров скрыт, клики и касания пропускает, реплики головы остаются над ним.
- Если WebGL недоступен или 3D не загрузилось, папки, каталог и кейсы работают без головы.
- Кнопки на телефоне — 48 px в высоту; кнопки в плашке наклона — 40 px.
