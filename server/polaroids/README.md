# Архив полароидов

Посетитель растягивает голову на главной и держит пару секунд — она считает «три, два, один», снимок выползает полароидом. На карточку можно налепить наклейки и написать пожелание. Сохранённая карточка уходит в архив: кружок с фотками на главной и страница `#/archive`, где их видят все.

Сайт статический, своего сервера у него нет. Общий архив — маленькая облачная функция в Yandex Cloud, как у лайков (`server/likes`), — один файл `index.js` без зависимостей. Пока её адреса нет в админке, полароид всё равно работает, но карточку видит только её автор: она хранится у него в браузере.

**Что хранится:** фото головы (webp или jpeg, 30–90 КБ), подпись до 56 знаков, какие наклейки и где приклеены, время. Ни имён, ни почты, ни cookie. Адрес посетителя не сохраняется: функция считает только, сколько карточек пришло с одного адреса за час (хеш адреса с секретной солью и номером часа), чтобы один человек не завалил архив.

**Сколько стоит:** для портфолио — ноль или копейки. У Cloud Functions и бессерверной YDB есть бесплатный объём каждый месяц; тысяча карточек — это около 60 МБ в базе. Нужен платёжный аккаунт Yandex Cloud с картой — без него бесплатный объём не включается. Сверьте цены перед подключением: [функции](https://yandex.cloud/ru/docs/functions/pricing), [YDB](https://yandex.cloud/ru/docs/ydb/pricing/serverless).

## Как завести — 15 минут, один раз

Всё делается в консоли [console.yandex.cloud](https://console.yandex.cloud). Ключей доступа заводить не нужно: функция ходит в базу от имени своего сервисного аккаунта.

1. **База.** «Managed Service for YDB» → «Создать базу данных» → тип **Serverless**. Можно та же база, что для лайков: у архива свои таблицы. На странице базы скопируйте **Document API эндпоинт** (начинается с `https://docapi.serverless.yandexcloud.net/…`).
2. **Сервисный аккаунт.** «Identity and Access Management» → «Сервисные аккаунты» → «Создать», имя `polaroids`, роль **`ydb.editor`**. Ключи ему не нужны.
3. **Функция.** «Cloud Functions» → «Создать функцию», имя `polaroids`. Редактор → среда **Node.js 22** (подойдёт и 18 или новее) → «Редактор кода» → файл `index.js` с содержимым одноимённого файла из этой папки (других файлов не нужно). Точка входа — `index.handler`. Таймаут — 10 секунд, память — 256 МБ. **Сервисный аккаунт** — `polaroids`.
4. **Переменные окружения** функции:
   - `DOCAPI_ENDPOINT` — эндпоинт из шага 1;
   - `MOD_KEY` — ключ модератора: длинная случайная строка, не короче 12 знаков (например, сгенерируйте пароль на 32 знака в менеджере паролей). С ним в админке скрывают карточки;
   - `ALLOW_ORIGIN` — адреса сайта через запятую: `https://pnemchenko.ru, https://www.pnemchenko.ru`. Карточки из браузера функция принимает только с этих адресов, и только им браузер покажет ответ — чужой сайт архив к себе не встроит. Откроете сайт где-то ещё (технический адрес Timeweb, будущий `.com`) — допишите адрес сюда, иначе карточки оттуда останутся только у автора. Пусто — любой адрес.

   Необязательные: `PREMOD=1` — все новые карточки скрыты, пока вы не покажете их в админке; `IP_HOUR` (по умолчанию 6) — сколько карточек в час можно прислать с одного адреса; `DAY_MAX` (по умолчанию 300) — сколько карточек в сутки принимает весь архив. Соль для хеша адресов функция придумывает сама и хранит в базе (своя — переменная `SALT`).

   «Сохранить изменения».
5. **Публичный доступ.** На странице функции включите «Публичная функция». Скопируйте её ссылку: `https://functions.yandexcloud.net/…`.
6. **Проверка.** Откройте ссылку с `?list=1` в конце — должно прийти `{"items":[],"next":""}`. Таблицы `polaroids`, `polaroids_img` и `polaroids_rate` создадутся сами при первом обращении. Если пришло `not configured: …` — функции не хватает эндпоинта или сервисного аккаунта.
7. **Подключение к сайту.** Админка → «Настройки сайта» → «Полароид» → «Адрес архива» → вставьте ссылку из шага 5 → «Опубликовать». Через минуту-две карточки с сайта начнут уходить в общий архив. Карточки, которые посетители успели сделать раньше, уйдут сами при их следующем заходе.

## Модерация

Новые карточки появляются в архиве сразу. Админка → «Настройки сайта» → «Полароид» → «Карточки в архиве»: вставьте ключ модератора (тот же, что в `MOD_KEY`) → «Показать карточки». У каждой карточки — «Скрыть» (можно вернуть) и «Удалить» (насовсем). Ключ хранится только в этом браузере и на сайт не публикуется.

- **Мат в подписи** функция ловит сама: такая карточка сразу скрыта и помечена «скрыта проверкой на мат». Список корней — в `index.js` (константа `RU`). Он короткий намеренно: лучше что-то пропустить и скрыть руками, чем спрятать невинное.
- **Картинку проверить автоматически нельзя.** Сайт присылает снимок головы, но написать запрос в обход сайта может любой. Если начнут присылать гадость — включите премодерацию: переменная `PREMOD=1`, и новые карточки ждут вашего «Показать».

## Что надо знать

- **Бюджет с уведомлением.** В консоли: «Биллинг» → «Бюджеты» → бюджет, например, на 100 ₽ в месяц с письмом при 50% и 100%.
- **Таблица `polaroids_rate`** — счётчики «сколько карточек за час». Её можно очищать когда угодно, на архив это не влияет.
- **Скрытая карточка** пропадает из архива сразу, но у того, кто её уже видел, фото могло остаться в кэше браузера — в списке архива её всё равно не будет.
- Политика безопасности страницы разрешает сайту загружать картинки и данные с `functions.yandexcloud.net` и API Gateway Yandex Cloud. Если архив будет жить где-то ещё, его адрес нужно дописать в `index.html` (строки `img-src` и `connect-src`) и в `admin/index.html` (строка `connect-src`).
